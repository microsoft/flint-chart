# 示例：自动布局

Flint 的自动布局只有一个目标：让图表适应数据和容器，同时保持图形元素清晰可读。数据变密时，算法会结合压力模型和倾斜优化原则（banking），调整画布尺寸、元素间距、宽高比和多面板布局。

主要权衡是在图表内部压缩元素，与将图表拉伸超出 `baseSize` 之间的取舍。拉伸受 `canvasSize` 或默认增长上限约束，因此图表在需要时获得更多空间，但不会无限增长。

下面四个示例分别展示一种布局压力：
[带状轴](#带状轴) 用于类别与分箱，
[连续轴](#连续轴) 用于密集点、时间序列与多条线，
[径向图表](#径向图表) 用于扇区与辐条，以及
[面积布局](#面积布局) 用于紧凑的二维空间。
这些示例使用默认的增长上限，便于观察数据密度、`baseSize` 和 `elasticity` 如何影响布局。

## 什么会被调整尺寸

自动布局只调整图表占用的空间：坐标轴跨度、分类间距、子图尺寸、径向空间、填充布局面积和整体绘图区都可以增大或缩小。数据、语义编码、颜色和格式保持不变。

## 布局模式

通过设置 `baseSize`、`canvasSize` 或两者选择模式：

| 模式 | 设置 | 行为 |
|------|------|------|
| **默认自动布局** | 均不设置 | Flint 以 `400 × 320` 为目标，数据密集时可以增大。 |
| **目标尺寸** | `baseSize` | Flint 以指定尺寸为目标，需要更多空间时仍可增大。 |
| **固定空间** | `canvasSize` | Flint 按该空间布局图表，使其在其中易读，适合尺寸固定的仪表盘和卡片；宿主需将绘制结果缩放进槽位（见「空间紧张时」）。 |
| **限制增长** | 两者都设置 | Flint 从 `baseSize` 开始，按需增大，但绘图区不会拉伸超过 `canvasSize`。 |

完整公式与实现细节见
[Auto Layout Algorithm](/documentation/layout-model)。

## 控制预算

探索时使用默认值。设置 `baseSize` 更改目标，仅当周围 UI 有硬性尺寸约束时再添加 `canvasSize` 上限：

```json
{
  "chart_spec": {
    "chartType": "Bar Chart",
    "encodings": {
      "x": { "field": "category" },
      "y": { "field": "value" }
    },
    "baseSize": { "width": 480, "height": 320 },
    "canvasSize": { "width": 720, "height": 480 }
  },
  "options": {
    "elasticity": 0.45,
    "minStep": 8
  }
}
```

此处图表目标为 `480 × 320`，可拉伸至 `720 × 480` 上限。
去掉 `canvasSize` 可让图表增长至 `baseSize × maxStretch`，或降低
`options.maxStretch` 以收紧固定仪表盘单元格的默认上限。

对于**固定槽位**，最简形式是单独设置 `canvasSize` —— Flint 将其视为图表填充且收缩适配的盒子：

```json
{
  "chart_spec": {
    "chartType": "Bar Chart",
    "encodings": {
      "x": { "field": "category" },
      "y": { "field": "value" }
    },
    "canvasSize": { "width": 320, "height": 240 }
  }
}
```

## 框较紧时

图表的标题、副标题、图例和装饰都在其框内。框较小时，它们会占去图表所需的空间——宽而矮的卡片上，长标题下叠放两个图例会把图压成一条。Flint 布局的最后一步会在绘制前发现这种情况。图上方的标题和一行图例是主题的设计，不会被改动；只有远大于此的标题区、占去宽度的图例，或宿主必须缩小到难以阅读的图，才需要修正。

修正采用**读者最不易察觉的最小改动**，只针对造成问题的部分——不会因为图例占了宽度而缩小标题——并且一次只做一项：

1. **图例在原来的一侧排成一行**，而不是叠放。
2. **名称折行**，先折行，绝不先截断：图例名称折行，图例保持原位；或当图表区本身对框过宽时，y 轴上的类别名按其绘制字号折行，绘图区不动。
3. **标题缩小一级**，标题不小于 13 px，副标题不小于 11 px。
4. **移动其中一个图例**，当多个图例共用一侧时：把图旁的第二个图例移到图下方排成一行，或把叠放的图例之一移到图旁。其余图例不动。
5. **把图例移到另一侧**——图旁，或在图上方/下方排成一行。
6. **标题缩小两级。**

所有能解决问题的改动都会被尝试，在能解决问题的改动中保留最温和的一项；两项相近时（例如图例在上方或下方），选择结果更易读的一项。

若框仍无法清晰地容纳图表，则**按原比例缩小绘图区**。标题和图例确定后，**绘图区会在框留下的空间内再布局一次**——标题区较高的图表，其条形会延伸到框多出的宽度——只有当文字不更小且整张图更好读时才采用；只运行一次。该步骤不会把图表放大布局再交由宿主缩小：无法修正的图表按其自身尺寸绘制，滚动还是缩放由读者或宿主决定。

读得好但比框略大的图表只会接受最温和的改动——图例在原侧排成一行、名称折行，或将 y 轴上折行的名称缩小一到两级（不小于主题字号的四分之三，使两行的行高变矮）——且只有在使整张图更接近其框且没有引入新问题时才采用。除此之外，本来就读得好的图表不会被改动，不会删去任何内容，也不会改变图表自身的形状。标题横跨整张图，包括图旁的图例；图上方或下方的一行图例也是如此。它们先按主题的位置摆放（居中的标题对准绘图区，图例从起始端排起），若在该位置会超出整张图的边缘，则只做最小的移动使其留在图内。只是把一个问题换成另一个问题的部分修正（例如把过宽的图改成过高）不会被采用，让本已过小的文字更小的改动也不会被采用。必须折行的标题按原字号折行，每行填满宽度（单独剩下的最后一个词会被均衡），只有当缩小一级能少占一行时才缩小。将 `options.canvasFit` 设为 `'off'` 可完全按原计划布局。

**绘制结果留在画布内。** 给定 `canvasSize` 时，若绘制结果仍超出画布（例如绘图区占满宽度时旁边的图例，或占满高度时上方的标题），图表会在保留上述改动的前提下按更小的空间再布局一次，由绘图区让出空间，使图例、标签和标题都留在画布内。绘图区每边最多让出一半，且不会为此删去数值或把原本水平的标签旋转。该步骤适用于单视图的 Vega-Lite 图表，报告代码为 `canvas-contain`，`canvasFit: 'off'` 时跳过；未给定 `canvasSize` 的图表布局不变。

**将剩余部分缩放进槽位。** 仍略超出框的绘制结果（密集的分类轴、分面网格、其他后端的图表）在宿主缩放进框后（不小于 70%）依然易读。按原始尺寸绘制图表的宿主，应将 SVG 或 canvas 按每边 `min(1, 框 ÷ 绘制尺寸)` 等比缩放（contain）；在服务端渲染时，应通过 `setTextMeasurer` 按渲染器的方式测量文字，使布局估算与实际绘制一致。

## 字体大小

文字（坐标轴刻度标签、轴标题、图例、图表标题）会围绕各后端的原生字号随画布自适应，
因此小图不会拥挤、大图也不会过小。要整体放大或缩小文字，可在 `options` 中设置两个基准字号：

```json
{
  "chart_spec": {
    "chartType": "Bar Chart",
    "encodings": { "x": { "field": "category" }, "y": { "field": "value" } }
  },
  "options": {
    "baseLabelFontSize": 14,
    "baseTitleFontSize": 16
  }
}
```

`baseLabelFontSize` 设置坐标轴刻度字号；`baseTitleFontSize` 设置标题类字号（轴标题、图例、
图表标题）。默认取各后端原生字号（Vega-Lite 10 / 11；ECharts 与 Chart.js 12 / 12；Plotly 12 / 14）。
密集坐标轴仍会在此基准上缩小、旋转并截断刻度标签以避免重叠。

要了解多面板布局和这些控件背后的模型，请继续阅读[自动布局算法](/documentation/layout-model)。
