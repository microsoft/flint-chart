# §1 概览

一次 Flint 编译回答两类问题。**数据说了什么**：字段类型、格式、排序、计数。**图表如何适应尺寸**：绘图区大小、band 步长、标签角度、图例和标题放在哪里、占用多少空间。布局计划让两类问题各成一个阶段，任一阶段都可以单独重新计算。

```
analyze(input)            → Analysis      仅数据与 spec
plan(analysis, context)   → LayoutPlan    尺寸、视图中的行、主题、后端配置、固定项
emit(plan, analysis)      → 后端 spec
```

| 术语 | 含义 |
|---|---|
| **分析** | 编译从数据和图表 spec 中得到的一切。它从不依赖尺寸或主题。 |
| **布局计划** | 所有占用空间或依赖可用尺寸的决策，汇集在一个与后端无关的对象中。 |
| **布局规划器** | 生成计划的模块（`core/plan.ts`）。 |
| **输出（emit）** | 把计划翻译为后端 spec 并加上样式。它不做任何布局决策。 |
| **结构** | 图表按含义所绘制的内容，由模板在计划之前声明（§5）。 |
| **装饰（furniture）** | 图表在绘图区周围绘制并占用空间的内容：刻度标签、坐标轴标题、图例、标题、分面标题。 |
| **固定项（pin）** | 交给规划器的固定值，来自作者，或来自已挂载图表保持其已绘制的值。 |
| **偏离** | 图表与主题或作者声明不同之处，附带原因报告（§6）。 |
| **移动 / 修正** | 移动只改变决策所在位置，绘制结果完全相同；修正有意改变输出。 |

# §2 为什么需要计划

在计划出现之前，Vega-Lite 编译是一个函数，各阶段相互渗透：

- Phase 1 用占位值确定绘图区尺寸（Vega-Lite 默认字号、固定的分面留白、估计的边距，如 30 px 的标题区），主题的字号和标题之后才到，因此带主题的图表可能超出 `canvasSize`，刻度数量读取的绘图区之后又被标题缩小。
- 主题在绘图区确定之后才决定空间：刻度数量、图例位置与换行、数值标签、标题换行与留白，并从输出的 Vega-Lite spec 中读取图表的事实。
- 每次运行时变化都要整次编译：缩放窗口、筛选、调整尺寸。实时布局按并未绘制的绘图区规划每个窗口，最多比挂载的窄 7%。
- 宿主能读取的绘图区尺寸是 Phase 1 的结果，而 band 轴、加宽的 band 标签和适配后的标题都会在之后改变它。

计划让每项决策在一个地方、用真实的值、对每组视图中的行做一次。

# §3 阶段

`assembleVegaLite` 由四次调用组成；每个阶段都是其输入的纯函数，从不修改上一阶段的输出。

| 阶段 | 函数 | 输入 | 输出 |
|---|---|---|---|
| 准备 | `prepareVegaLite` | 输入 spec、主题预设 | 模板、图表属性、主题 |
| 分析 | `analyzeChart`（`core/analyze.ts`） | 数据行、图表 spec | `ChartAnalysis` |
| 计划 | `planLayout`（`core/plan.ts`） | 分析、`PlanContext` | `LayoutPlan` |
| 输出 | `emitVegaLite`（`vegalite/assemble.ts`） | 计划、分析、主题样式 | Vega-Lite spec |

**分析。** 类型预处理（`resolveChannelTypes`）推断每个通道的类型，使编码覆盖得以应用；随后一次语义处理解析整理后的编码。分析保存全数据事实（类型、格式、零点、定义域约束、排序），并保留对转换后数据行的引用；`shapeRows` 整理宿主提供的数据行。读取数据范围的事实（`temporalFormat`、`zero`、定义域约束、发散中点）保持全数据的值，因此窗口沿用整张图的格式。

**计划。** `planLayout(analysis, context)` 做出所有布局决策（§4）。其上下文：

| 输入 | 字段 |
|---|---|
| 尺寸 | `size.baseSize`、`size.canvasSize` |
| 视图中的行 | `rows`：全部行，或窗口、筛选留下的行 |
| 主题 | `theme`，在计划中落地为 `DesignDecisions`（§6） |
| 后端配置 | `profile`：默认值、后备值、band 留白、文本测量器、间距（§7） |
| 固定项 | `pins`：绘图区、标题、预留、坐标轴标签（§8） |

计划分两部分：先确定绘图区之前的内容（选项、分面网格、溢出截断），再由 `planAroundPlot` 布局绘图区并决定其上与周围的一切。当 band 步长适配画布剩余空间时，`planAroundPlot` 运行两次（§4.8）。

**输出。** `buildVegaLite` 是模板阶段：模板按计划的尺寸实例化其骨架。输出阶段随后写入计划的决策，运行主题实现以施加样式，并写入图例布局。主题实现接收计划的决策，不修改它们。

# §4 计划决定什么

`LayoutPlan` 保存每项决策及其依据的事实。每项决策移入计划时保持原有方法；修正只纠正其输入（§13）。

## §4.1 绘图区与步长

- **绘图区**（`plan.plot`）：band 轴的跨度是步长乘以 band 数（截断占位再加一个 band），按模板声明的形状（`bandAxes`：普通、嵌套，或带内缩的点比例尺）；主题的条形填充来自 `resolveBandFraction`。自行决定尺寸的模板在 `planPlot` 中决定其绘图区（饼图、玫瑰图、雷达图、地图、分面小提琴图、日历）。组合图的绘图区为单个面板。
- **步长** 来自 `computeLayout`（[自动布局算法](design-stretch-model.md)的尺寸模型），两行 band 标签在计划中规划（`planBandLabels`）。布局报告哪些步长适配了空间（`xStepFitted`、`yStepFitted`）。
- **band 化连续轴跨度**（`plan.bandSpans`）：band 化的定量或时间轴覆盖其数据，并在两端各多出半个 band，使边缘的 band 完整显示。

## §4.2 坐标轴

- **刻度标签**（`plan.axisLabels`，`core/axis-labels.ts`）：每条轴的字号、字体、长度上限、间距、行高和角度，来自拟合的标签尺寸、主题偏好和计划事实。主题字号保持不变，除非布局必须缩小标签以适应 band（`crowdedFrom`）。类别名能否水平排列只有一条实测规则：渲染器测得的最宽名称加 6 px 间距，与 band 比较。放不下的名称转为 −45°，或在 band 窄于旋转后的一行时竖排，除非布局已拟合角度；主题要求水平但无法成立时予以拒绝（`straightRefused`）。自行标注坐标轴的模板通过声明说明其决策（`LayoutDeclaration.axisLabels`），计划将其作为固定项。
- **坐标轴标题**（`plan.axisTitles`）：模板自己的标题，否则取编码携带的标题，仅当坐标轴显示该编码的字段。
- **定义域与范围**（`plan.domains`，`core/measure-domain.ts`）：Flint 的语义定义域规则（按堆叠总量判断约束、零点下限、堆叠的整洁顶端），以及每条度量轴必须显示的值；零点遵循模板声明的基线。
- **刻度尺**（`plan.rulers`，`core/ruler.ts`）：带主题的单视图度量轴的定义域与刻度值。步长取最接近主题刻度间距的 1、2、5 步长，按实测标签保持间隔；有网格的自由端取整到步长，无网格的按后端方式取整。模板自管的轴、聚合、分箱、对数比例尺、组合图、实时布局和无主题图表保留后端的刻度尺。

## §4.3 标题

`planTitle`（`core/title-plan.ts`）把单视图图表的主标题和副标题适配到其区块：缩小一档字号，或折成填满区块的多行（末行不留孤行），多出的行高从绘图区扣除。副标题包括作者的副标题以及主题移入的坐标轴标题。标题在任何环境中都用宽度表按其自身字体与字重测量，因为即使在没有 canvas 的环境中编译，标题仍以真实字形绘制；只要超出区块就会适配。自行计算类别轴的模板会说明类别名称（`AxisDescription.categories`），使区块计入这些标签。

## §4.4 图例与序列名称

- **在哪里命名序列**（`planLegendPlacement`，`core/series-end.ts`）：主题的序列末端名称仅在有末端的线、非类别轴的序列、开放的线和空闲边距上成立，并在一行内错开；否则采用主题排序的下一个位置。自己打印末端标签的图表保留其标签（`legend.ownNames`）。
- **显示哪些图例**（`planLegend`，`core/legend-plan.ts`）：主题去掉的标题、数值图例的整数样本、颜色折叠（"Others (N)"，覆盖整张图）、每个图例的条目。
- **图例布局**（`planKeyLayout`，`core/legend-layout.ts`）：每个图例的边、列数、标签与标题换行，以及同一边的图例如何排布，按代价搜索。图例按 Vega 的方式测量。主题排序的位置代价低；未排序的边代价高于多一行图例。主题的 `arrangement`、`titlePosition` 和 `align` 是同样定价的偏好，只在图例会溢出时让步并报告偏离。计划决定图例之间的间距（1.5 倍标签字号，`spread` 时为图例余下的空间）和锚点；同行图例居中对齐。

## §4.5 数值标签

`planValueLabels`（`core/value-label-plan.ts`）：打印的度量或不打印的原因、形式（单元格、沿扇区、分段居中、标记末端）、在标记内或末端之外、保留标签的最小分段，以及标签在条形末端之外所需的留白或内缩。分段是容纳多行的 band（`segmentedBands`），与定义域读取的事实相同。

## §4.6 标记

- **类别顺序**（`plan.orders`）：作者的顺序，否则为字段自身的顺序；模板声明的顺序替换数据顺序，或在固定时替换任何顺序。
- **尺寸范围**（`plan.sizes`）：主题为定量值设定的范围，其最小面积作为下限，否则为每行画布的合理份额。
- **散点**（`plan.pointSize`、`plan.points`）：主题的点大小，在点墨量超过所在面板 12% 时缩小；在没有锚定的点的轴上，比例尺按实际点的外半径留白。

## §4.7 分面

`planFurniture`（`core/furniture-plan.ts`）：面板间距、分箱的定量分面、包裹分面的面板是否各用独立 y 比例尺，以及平放 y 标题的抬升及其占用的空间。

## §4.8 为装饰保留的空间

当 band 轴把步长适配到空间时（主题的 `bandStepFit` 加上超过基准尺寸的 `canvasSize`），可用空间是画布减去装饰。计划先不保留空间布局绘图区，测量所决定的装饰（`measureReserve`，`core/furniture-reserve.ts`：最宽刻度标签、旋转的坐标轴标题、侧边与上下的图例、序列末端名称、主副标题首行、平放 y 标题、列分面标题），再保留这部分空间（不超过画布的 40%）重新布局。只测量一遍：变窄的步长导致的标签旋转不再测量。结果为 `plan.reserve`，每次重新规划时固定。

## §4.9 视图

`plan.views`（`core/views.ts`）以树说明图表绘制的视图及其排列：`view`（绘图区、一列文本或卡片，带其绘图区尺寸）、按行或列排列的 `concat`，以及在网格上重复一个视图的 `facet`（列数、行数、面板数）。间距是后端在相邻视图边界之间保留的空间（含坐标轴和标题），按其实际绘制。单视图图表是一个 `view`；按列与行字段的分面由字段和布局的换行规划；自行组合视图的模板自己说明（§5）。

视图树记录实际绘制的内容。分面面板按计划在其间绘制的间距再布局一次，计划随后保持该间距；输出把该间距写在 Vega-Lite 读取之处：每个行与列字段、分面算子的 spec，以及主题移动分面之后再写一次；只有换行分面的配置才写 `{ row, column }`，因为没有自身间距的字段会整体取用配置中的一对值。

# §5 模板与计划

主题的空间决策需要在模板构建之前知道图表绘制什么。因此模板按含义描述其图表（`ChartStructure`，`core/structure.ts`）：标记；每条轴的类型、字段（范围为两个）、派生度量或分组、基线、范围、是否取整、是否由模板自管（`ownScale`）、拟合曲线、反向、类别顺序；颜色区分的序列；堆叠意图；图例；以及模板设定的标题。默认值读取骨架；`instantiate` 构建其他内容的模板编写 `structure`，并通过一个函数与 `instantiate` 共享条件。

模板对自身布局做出的决策通过其声明说明（`declareLayoutMode`）：band 形状、轴标记、参数覆盖，以及它自己设定的刻度标签。

组合多个视图的模板通过 `planViews` 说明它们，在计划中于绘图区之后运行：雷达图的面板、人口金字塔的两半、小提琴图的面板、Sparkline 的三列条带、KPI 卡片和 Bar Table 的各列。每个模板把自己的尺寸方法放在计划调用的函数中（`barTableLayout`、`sparklineSizes`、`kpiGrid`）；`instantiate` 绘制它在 `context.views` 中找到的尺寸与间距。

`tests/chart-structure.test.ts` 在每个生成的测试用例、无主题和每个预设下，比较模板声明的结构与从其构建结果读出的事实，因此模板的两部分不会偏离。

# §6 主题与计划

**原则。** 不占空间的是样式，由主题决定：颜色、字体、字重、线条、标记形状。占空间的是布局，主题声明偏好，规划器在其中决定：图例位置与排布、标签角度与字号、band 步长、数值标签、标题位置。规划器保持偏好，除非图表无法承载，并报告偏离。优先级：作者固定项，然后是主题标为固定的项，然后是主题的偏好，最后是规划器的默认值。

**主题在哪里运行。** 主题落地（`groundTheme`，`core/theme/ground.ts`，与 Plotly 共享）在计划中基于结构和作者标题运行，返回 `DesignDecisions` 作为 `plan.design`。规划器从中读取主题的布局值。主题实现（`realizeThemeVegaLite`，`vegalite/theme.ts`）写入样式并翻译其收到的计划决策；它不决定空间。主题的图表默认值只能设定图表外观：分析读取的键会被报告并丢弃。

**报告。** `_theme.report` 只列出偏离：图表与主题或作者声明不同之处，或声明的选项无法用于此图表之处。每条记录包含所涉及的 ThemeSpec 路径、稳定的 `code`（如 `labels-straight-refused`、`dots-shrunk`、`keys-arrangement-gave-way`）以及说明原因的消息。按声明应用的设置不会报告。测试读取 code 而非措辞。主题的完整决策仅在请求时（`options.themeDecisions`）作为 `_theme.decisions` 附加；工具可从会话读取完整计划。

# §7 后端

规划器接受后端配置（`BackendLayoutProfile`）：

| 项 | Vega-Lite |
|---|---|
| `defaults`、`fallbacks` | 标签 10 / 标题 11 px，不做 band 步长适配，分面留白与间距 |
| `nestedBandPadding` | 内外均为 0.2 |
| `spellField` | 转义字段名中的 `.`、`[` 和 `]` |
| `measureText` | 宿主声明的渲染器测量方式（`setTextMeasurer`：MCP 服务器的 canvas），否则浏览器中为宽度表（`TEXT_WIDTHS`，由 `npm run gen:text-widths` 从 Chrome 的 canvas 生成），否则 Node 中为 Vega 的 0.8 em 估计 |
| `spacing` | Vega 的坐标轴、图例和标题默认值：刻度 5、标签间距 2、标题间距 4、图例偏移 18、标题偏移 4、副标题间距 3 |

只有 Vega-Lite 使用计划。ECharts、Chart.js 和 Plotly 调用 `computeLayout` 并自行做布局决策；Plotly 共享主题落地。计划中没有任何 Vega-Lite 专有内容，因此每个后端可通过自己的输出器接入（§12）。

# §8 会话、固定项与实时布局

`openVegaLiteSession(input, { pins })` 保存已挂载图表的分析和计划，并提供 `replan(change)`。行的变化（`{ keep }`、`{ rows }`，或 `{ window: { x } }` 表示 x 窗口内的行）把同一分析的这些行规划进图表的框架，并保持：

| 固定项 | 保持方 |
|---|---|
| `plot` | 数据窗口（`pinPlot`）：保持绘图区框而非步长，因此把全部行重新规划到其自身绘图区是不动点 |
| `title` | 每次重新规划：挂载时的标题适配 |
| `reserve` | 每次重新规划：为装饰保留的空间，使视图中的行不会通过它改变步长 |
| `axisLabels` | 作者或宿主保持标签字号或角度；计划的拥挤与拒绝判断不再作用于固定的部分 |

尺寸的变化（`{ size }`）为新空间重新规划整张图表：框架、标题适配与保留空间都重新规划，之后行的变化规划进这个框架。

实时布局从全数据分析出发、固定绘图区，规划每个缩放窗口（通过 `liveLayoutPlanner` 调用 `replan({ window, pinPlot })`）；筛选通过 `replan({ rows })` 重新规划。`surface.layout.plot` 在按该尺寸绘制单个绘图区的图表上报告计划的绘图区，随筛选的重新规划和尺寸调整变化，在组合图、带类别导轨的图表以及后续阶段改变了绘图区时为 undefined。`surface.layout.views` 与 `surface.layout.block` 报告每个已绘视图的框，以及视图连同坐标轴与标题构成的整体框，在每次渲染后从 Vega 的场景读取（`readDrawnLayout`），每个视图取计划给出的角色。位置不做规划：Vega 把坐标轴放在面板所绘内容之外，只有渲染才知道；静态编译只报告尺寸。

**原地调整尺寸。** 为某个空间挂载的图表（`availableSize`；React `fit="relayout"`）把布局值绑定到一个信号（`bindLiveValues`）：每个承载布局值的坐标轴、标题、图例、分面标题、比例尺和标记属性都改为读取该信号，原本嵌在表达式中的值改由值信号承载（时间刻度规划器的输入、缩放边距）。`surface.relayout(size)` 在新尺寸下重新规划，按挂载时的方式生成下一个 Vega spec，并与已挂载的比较（`liveValuesChange`）：两者只在绑定值、信号值、视图尺寸，以及其余不变的内联数据集的数据行（规划为该空间算出的行，例如标签的截断长度）上不同时，推送这些值并运行 Vega 的 enter 编码集（Vega 只在 enter 时编码图例标签）；否则返回 false，由宿主重新挂载。重新规划针对屏幕上的数据行（筛选或宿主给出的行）。推送保留选择、筛选、缩放和更新。React 先尝试 `relayout`，返回 false 时重新挂载。重新挂载保留宿主的更新，但不保留读者的状态：跨过某个结构决定（图例移到绘图区下方并改为横排、标签转角、增加图层）的尺寸变化，会在那一步清除一次读者的选择、隐藏的系列和缩放。要跨重新挂载保留它们，需要交互能交出自己的手势状态。

# §11 成本

在浏览器中编译对比语料（11,157 个用例），计划之前每张图 1.6 ms，主题空间决策与文本实测移入后 3.9 ms，按阶段剖析规划器后为 1.17 ms；规划视图后为 1.33 ms，因为 Bar Table 与 Sparkline 构建 spec 时仍会再运行一次尺寸计算，且分面图表布局两次（§4.9）。差别来自三个热点，每项修正都是移动（每次编译不变）：

| 热点 | 之前占比 | 修正 |
|---|---|---|
| 间距刻度尺为每个 1、2、5 步长（低至跨度的千分之一）生成并测量标签 | 30% | 从最接近目标的步长开始尝试；第一个通过的即为结果 |
| 文本宽度：每个字符一次正则匹配，每次调用解析字体栈 | 22% | 码位区间判断，每个测量器只解析一次字体族，按文本保存宽度 |
| 图例规划器在每条边上拟合每个图例，并为每个列数重新换行每个标签 | 27% | 相对的边共用一次拟合；换行及其成本按宽度与行数保存 |

现在没有主导阶段：放置图例 13%，主题落地 13%，分析 20%。为某个空间挂载的图表绑定实时值多花 0.17 ms；一次原地调整 1.5 ms（重新规划 0.84、Vega-Lite 编译 0.57、比较 0.08），而重新挂载还要重新解析 Vega spec 并重新挂载交互。

与重新设计之前的编译（e55b7dd）对比，2026-10-12 在浏览器中测量：同样 11,171 个用例取三轮最佳；读者实际等待的时间取每第八个用例（Flint 编译、Vega-Lite 编译、Vega 解析与首次运行，无界面）：

| 每张图 | 之前 | 现在 |
|---|---|---|
| 仅 Flint 编译 | 1.54 ms | 1.33 ms |
| 挂载 | 4.9 ms | 4.8 ms |
| 缩小 20% | 4.4 ms（重新编译并挂载） | 3.7 ms（46% 原地推送，其余重新挂载） |
| 保留一半行的筛选 | 3.6 ms（重新编译并挂载） | 2.6 ms（重新规划，推送尺寸与数据行） |

计划比旧编译做得更多，但上面的剖析修正足以抵消；已挂载的图表也不再为每次调整尺寸或筛选重新编译并挂载。

# §13 决策记录

每项决策移入计划时保持其方法；修正纠正其输入。以下记录每个选择的原因及其改变。

**阶段与会话**

- 类型预处理后只做一次语义处理：预处理原先完整做了两遍（7,200 行折线图 53 → 44 ms）。
- 实时布局忠实于 `plan(analysis, { window })`，而非窗口的重新编译：窗口保持全数据事实和挂载的绘图区。
- 固定绘图区保持框而非步长：由框推导步长会使缩放回到全范围时标签跳动。
- 图表保持其组成部分时，调整尺寸原地推送重新规划的值。设置器由编译的 spec 生成，而非手写表：尺寸调整改变的值分布在坐标轴、标题、图例、分面标题、比例尺和标记属性上，只推送尺寸只适用于 1.5% 的调整。与下一个 spec 的比较决定推送还是重新挂载，因此绑定遗漏的值会重新挂载而不是画错。
- 表达式嵌入的值改为值信号（时间刻度输入、缩放边距），因此缩放后的图表在调整尺寸后保持缩放。
- 规划器的成本靠搜索顺序与保存的结果修正，而不是换更便宜的规则：每项修正都是移动，语料编译不变。

**视图**

- 视图树说明实际绘制的内容，因此与 Vega 的核对是精确的；模板要求而 Vega-Lite 从未绘制的间距（小提琴图相接的面板），计划保留读者看到的间距。
- 分面面板按其间绘制的间距布局，像为装饰保留空间一样做一次修正（2,324 次编译）。输出把间距写在 Vega-Lite 读取之处；主题的 `{ row, column }` 间距曾使小提琴图的各行相撞。
- 模板按计划的方式、以主题正文字体测量文本（378 次编译）；布局未设定之处保留模板自己的配置（480）。
- 分面面板像同尺寸的单一绘图区一样绘制主题的刻度尺；换行面板各自缩放的 y 保留自己的刻度。分面图表的主题标签加入面板的 spec；它们曾被丢在分面旁边（610 次编译恢复了标签）。
- 每个分面面板都立在一条按 x 轴线绘制的底线上，位于其自身底边，坐标轴不再画线：主题原先把最低的网格线当作这条线，在有点填充的面板上会悬空，在底行与坐标轴线重叠成双线，而以通道给出的分面则完全没有。上下排列的面板在行间为 y 刻度标签保留空间，除非主题把标签收进面板内；小提琴网格的各列相接。
- 多视图图表按其视图（含间距）所跨的宽度确定标题与图例，方法与单一绘图区相同（252 次编译）；主题不再从 spec 测量单个面板。
- 分面图表的 y 轴在面板外 1–4 px，因为 Vega 把它放在面板所绘内容之外；按面板边缘布局（`bounds: 'flush'`）会使分面字段标题挤进各面板标题。没有轴线的坐标轴改为去掉无法与网格相接的刻度，有轴线时剩下的 1 px 保留。
- 位置只报告不规划：把整体框量到 1 px 意味着模拟 Vega 基于边界的布局，而计划不做模拟；已挂载的图表从场景读取视图与整体框，精确且廉价。标题、图例与封闭横线使用整体框估计，几个像素的差别看不出来。
- 主题的封闭横线由计划决定：按不含画布下限的整体框确定宽度，其空间在高度为给定值时从绘图区取出（905 次编译）；把网格延伸到绘图区外作为刻度的主题，其空间被保留（308）。

**模板**

- 模板描述结构，并与其构建结果对照：其他方案是 `instantiate` 之后的第二个计划阶段、拆分每个模板或测量输出的 spec，要么依赖 Vega-Lite，要么工作量过大。对照检查使声明的事实可靠。
- 按含义而非 Vega-Lite 的视角描述结构：数值标签不用于计算得出的度量，蜡烛图不再用图层字段命名坐标轴（107 次渲染）。
- 声明 band 形状而非输出留白：每个跨度都准确，无需复现 Vega-Lite 按标记的默认值。
- 模板声明基线、范围、顺序和自己的刻度标签：模板自身的方法是参照，计划读取它而非与之矛盾（日历的月份首字母曾按从未发生的 −90° 旋转锚定；48 次渲染）。

**归属**

- 每项决策只有一个所有者：只有能给出后端必须遵循的值时计划才拥有该决策；不存在半归属。
- 计划完整拥有刻度尺（定义域、步长、刻度值）：仅凭刻度数量提示，Vega 只在 24% 的带主题轴上达到主题间距 ±10%（1,245 次渲染；间距与目标之比中位数 1.11 → 0.93）。
- 计划保持低成本：基于聚合与简单规则决策，从不模拟后端；后端事实来自其配置。
- 不占空间的主题样式归主题；空间归规划器，在主题偏好之内（§6）。排序的位置、排布与标题位置是带代价的偏好而非硬性清单：11 个预设中有 7 个只列出一条边，否则过高的图例将无处可去。
- 主题声明意图，规划器计算像素：图例对齐方式而非间距。

**输入的修正**

- 堆叠是容纳多行的 band，而不是条形上的颜色：分组百分比不再截断，热图不再被挤压（128 次渲染）；数值标签遵循同一事实（22 次）。
- 按渲染器的方式测量文本（108 次渲染）；图例按其标签测量，放得下的图例共享一行。
- 保留空间按计划所做决策测量，取代仅凭是否存在就计入图例的固定边距（2,379 次编译；步长中位数 +3 px）。
- 用一条水平标签规则取代两个估计；放不下的名称按 band 转为 −45° 或竖排（968 条轴不再使用 Vega-Lite 的竖排默认值）。
- 散点按其所绘面板而非布局子图确定大小（132 次渲染）。
- 主题实现在计划之后做出的决策移入计划：主题的尺寸范围、共享比例尺上的数值标签留白、图表是否自己打印末端标签。
- 报告只列出偏离：确认类条目占了大多数，重复的决策占了大部分字节。
